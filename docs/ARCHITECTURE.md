# 仕組みの解説

外部の素材（3D モデル、画像、音声ファイル）を 1 つも使わず、すべてをプログラムで作っています。
ソースは約 4,000 行の素の JavaScript で、ビルドは「5 つのファイルをつなげるだけ」です。

| ファイル | 役割 |
|---|---|
| `src/head.html` | 画面の HTML と CSS（タイトル、HUD、設定、結果の各画面） |
| `src/core.js` | 描画の土台。雲のシェーダー、合成、ブルーム、最終の色調整、台風の形 |
| `src/world.js` | 物を作る。海、機体、島と基地、港、灯台、船、竜巻 |
| `src/audio.js` | 音。合成した音楽、雷、エンジン、風雨、効果音 |
| `src/game.js` | 進行。操縦、僚機、局面、トラブル、カットシーン、当たり判定、HUD |

## 1 コマが描かれるまで

1. **物体を描く** — 海、島、機体などを、明るさの幅が広い（HDR の）画面と奥行きの画面に描きます。
2. **雲を描く** — 半分の解像度で、画素ごとに視線を伸ばし、雲の濃さを少しずつ積み上げます（後述）。
3. **時間方向にならす** — 前のコマの雲と混ぜて、ざらつきを消します。カメラが飛んだときは混ぜません。
4. **合成** — 空、巻雲、高さに応じたもや、雲を重ねます。カットシーンでは隅の暗がりも足します。
5. **発光するもの** — 雷、マーカー、噴射の光などを別に描いて重ねます。
6. **ブルームと光芒** — 明るい所をにじませ、太陽から放射状の光の筋を出します。
7. **仕上げ** — 輪郭のぎざつきを取り、レンズの雨粒、被写界深度、雨の筋、色調、周辺減光をかけます。

## 台風の形

台風は、関数 1 つで決まる「どこにどれだけ雲があるか」の分布です。
中心からの距離で、目（半径 2.4km）、壁雲（〜4.6km）、らせん状のレインバンド（〜15km）を作り分けています。

同じ式を 2 か所に持っています。シェーダー側（`stormCover`、雲を描く）と JavaScript 側（`stormAt`、雨・揺れ・暗さを決める）です。
片方だけ直すと、見た目と体感がずれます。

## 雲の描きかた

画素ごとに視線を伸ばし、決まった歩数だけ進みながら雲の濃さを足していきます。工夫は 3 つです。

- **粗い歩幅と細かい歩幅** — 何もない所は大股で進み、雲に入ったら 1 歩戻って細かく刻みます。雨のもやだけは大股のまま積みます。
- **歩数の配分** — 手前の雲の薄い縁で歩数を使い切ると、奥の雲まで届かず穴が開きます。残りの歩数で 18km 先まで届かなくなりそうなら、粗い歩幅に切り替えて必ず進みます。
- **雲の模様** — 96×96×96 と 32×32×32 の 3D のノイズ画像を起動時に計算し、大きな形と細かい崩れに使います。

太陽の方向へも数歩たどって、どれだけ光が届くかを見ます。雲の縁が明るく、底が暗くなるのはこのためです。

## 海

カメラについて動く同心円状の網を、3 本のうねりで上下させ、細かい波は 6 段のノイズを毎段回転させて重ねた傾きで表します。
数キロ規模の風のむら、積雲の影、島のまわりの浅瀬と磯波、港の中の静かな水面を、場所に応じて切り替えます。

## 機体

胴体は回転体、翼は翼断面をいくつか並べてつないだ面です。7 種の形は「翼断面の位置の表」と数個の指定だけで作り分けています。
動翼、放電索、装甲板、翼端灯などは、その表から位置を計算するので、形を足すときは表を 1 行足すだけで済みます。

汚れ、雨だれの筋、排気の煤、外板の継ぎ目は画像ではなく、シェーダーの中で計算しています。

## 基地と港

地形は高さを返す関数 1 つ（`islandH`）で、滑走路・駐機場・港の敷地だけ平らにならしています。草・岩・砂の絵柄も起動時に描きます。

動かない部品は、起動時に材質ごとに 1 つの形へまとめます（`mergeStatic`）。基地の描画単位はこれで約 3,300 から約 1,100 に減りました。
港・灯台・滑走路まわりの細部は、8km 以上離れると描きません。

## 当たり判定

- **地面と海** — 高さの関数と比べるだけです。
- **建物** — 起動時に、背の高い部品 1 つ 1 つを囲む箱を集めておきます（約 230 個）。格納庫だけは外殻とし、入口から中へ飛べます。
- **細い柱** — 幅が狭く背の高い箱は「柱」として扱い、機体から見て左右どれだけずれているかで、胴体に当たったか主翼に当たったかを判別します。

## 奥行きの精度

遠くの物ほど、前後を見分けられる細かさが粗くなります（距離の 2 乗に比例）。
そのままだと、壁から数 cm 浮かせた窓枠が 1km 先でちらつきます。
そこで「ここより手前は描かない」距離を毎コマ調整し、近くに物がないときは最大 20m まで遠ざけて精度を稼いでいます。

## 音

音声ファイルは使わず、WebAudio で合成します。

- **音楽** — 場面ごとの和音進行と拍の型を持つ小さなシーケンサーです。
- **雷** — 放電路を折れ線で作り、各区間から耳までの距離の差で音がずれて届く様子を計算して、遠雷のごろごろを作ります。
- **エンジン** — 3 つの発振器と雑音を混ぜ、カットシーンではカメラとの距離と向きで音量・左右・高さを変えます。

## 進行とカットシーン

局面（接近 → レインバンド → 壁雲 → 目 → 再攻撃 → 帰投）は状態機械です。局面の変わり目が再挑戦の起点になります。

カットシーンは「ショットの並び」で書いてあり、各ショットは長さ・準備・毎コマの更新を持ちます。
始めと終わりは、通常の追尾カメラとなめらかにつなぎます。

## 省電力

タイトルや一時停止の画面は毎秒 30 コマに落とし、5 分操作がなければ描画を止めます。タブが裏にあるときも止めます。
